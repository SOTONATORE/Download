- Ключи с `api_key`, `token`, `secret`, `password` в конфиге отвергаются (SPEC 0.1).
- Входы workflow и аргументы CLI переопределяют файл и проверяются по той же схеме.
- `check` проверяет конфиг раньше входных файлов, поэтому ошибка видна на этапе preflight, до аренды карт.
- Новая зависимость: `pyyaml>=6.0` (добавлена в `requirements-dev.txt`).

## 2. `prompts.json`: статус и требование (уточнение раздела 4)

**Статус файла.** `prompts.json` — файловый чекпоинт Gemini. Он лежит в основном Release как служебный
файл, не как клип. Он хранит промпты и статусы, а источником правды по готовым клипам остаётся сам Release.

**Требование.** При старте оркестратор до первого вызова Gemini скачивает `prompts.json` из основного
Release. Затем проверяет хэш `final.srt`, имя модели и профиль. Если файла в Release нет, запуск начинается
с пустого состояния. Если хэш, модель или профиль не совпадают, запуск останавливается до первых трат, с
понятным текстом. Номера, у которых промпт уже есть, в Gemini не отправляются.

**Состояние кода сейчас.** Запись `prompts.json` локально и заливка в Release (шаг `finalize-release`) есть.
Скачивания при старте нет: протокол `ReleaseStore` не содержит метода скачивания. Следствие: на новом раннере
файла нет, и Gemini вызывается повторно для номеров, у которых клипа ещё нет в Release. Клипы, уже лежащие в
Release, пропускаются в любом случае. Это вопрос расхода квоты, а не потери результата.

## 3. Открытые пункты (не закрыты этим изменением)

1. **Скачивание `prompts.json` при старте не реализовано.** Нужно: метод скачивания в `ReleaseStore` и
   `GhReleaseStore`, шаг старта в `Orchestrator`, тесты на заглушке. Вынесено отдельной задачей, потому что
   меняет поток запуска.
2. **`gemini_batch_size` 20 → 100.** Подтвердить. Если нужно прежнее поведение, поставьте 20 в конфиге.
3. **Отчёт аудита не был приложен к загрузке.** Расхождения выше найдены сверкой SPEC, конфига, workflow
   и кода. Если в отчёте есть пункты сверх этих, пришлите его, и они будут разобраны отдельно.
4. **Дублирование значений в `generate.yml`.** Входы повторяют значения по умолчанию из конфига. Сейчас они
   совпадают. Чтобы конфиг стал единственным источником, значения по умолчанию у входов можно убрать, а
   пустой вход не передавать в CLI. Это изменение workflow, в этом наборе не сделано.
5. **Аргументы CLI с секретом.** `argparse` при ошибке типа печатает введённое значение. Секреты передавать
   аргументами запрещено (SPEC 0.1, п.3), но это поведение стоит учитывать при разборе ошибок.
