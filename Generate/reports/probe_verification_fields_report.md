# Отчёт: поля подтверждения хоста в пробе Vast (verification, is_vm_deverified)

Дата: 13.10.2026. Файлы: `Generate/tools/vast_probe.py`, `Generate/SPEC.md`, этот отчёт. Production-код не менялся (`Generate/core/`, `Generate/cli.py`, оркестратор, воркер). Живой прогон после правки не выполнялся: проба запускается на GitHub, здесь выполнена только офлайн-проверка на заглушках (раздел 2).

## 1. Что изменено в пробе

Исходная проблема: значения полей подтверждения печатались только в блоке с фильтром `verified=True` и только если тот поиск возвращал предложения. Прогон 13.10.2026 дал 5 предложений без фильтра и 0 с фильтром, поэтому значения не печатались.

Изменения в `Generate/tools/vast_probe.py`:

- **Новая функция `_verification_fields_unfiltered(offers, show_count)`.** Вызывается в `main()` на новом шаге «1а» сразу после вывода первых предложений и до сверки с `verified=True`. Печатает значения полей `verification` и `is_vm_deverified` у каждого предложения ответа без фильтра (до `show_count` строк на экран). Если поля нет, печатается «поля нет». Значения проходят через `_snippet`, секреты заменяются на `***`. Возвращает блок для `probe_result.json`: сырые значения у всех предложений, которые пишутся в файл (до `RESULT_OFFERS_LIMIT` = 200).
- **Новая функция `_raw_text(value)`.** Превращает значение в текст для печати: JSON `null` печатается как `null`.
- **Новые константы:** `VERIFICATION_FIELDS` (`verification`, `is_vm_deverified`), `VERIFICATION_STATUS` (`UNVERIFIED`), `VERIFICATION_BLOCK_KEY` (`verification_fields_unfiltered`), `FIELD_MISSING_TEXT` (`поля нет`).
- **`main()`:** инициализируется `verification_block`, после шага 1а в файл пишется ключ `verification_fields_unfiltered`.
- **Комментарии и докстринг модуля:** обновлены. Имена полей помечены как подтверждённые живым ответом, смысл значений помечен UNVERIFIED.

Без изменений: `_check_verified` и его два счётчика, `_verify_field_names`, коды выхода (0, 2, 3, 1), формат `probe_result.json` (добавлен только новый ключ), `_sanitize`, `_snippet`, маска секретов, production-фильтр `verified` (по умолчанию False).

## 2. Строки, которые проба печатает теперь

Пример ниже получен офлайн на **заглушечных (MOCK) данных**, не из ответа Vast. Ключ `api_key` в значении заглушки показан в маске, потому что тест подставлял тестовый секрет `TESTKEY-12345`; секрет в выводе не появился.

```
  #1: id=111; verification=MOCK_A; is_vm_deverified=False
```

Если предложений нет: `Предложений нет: поля подтверждения не проверены.` Если элемент ответа не объект: `  #N: не объект`.

Блок в `probe_result.json` (MOCK, сокращённо):

```json

  "offers": [
```

Офлайн-проверка (заглушки Vast и Hugging Face, `httpx` подменён, сети не было) подтвердила: код выхода `main()` равен 0; секрет не попадает ни в печать, ни в файл; ключ `verification_fields_unfiltered` записан. Это не результат живого Vast.

## 4. Что помечено UNVERIFIED и где

| Что | Где помечено |
|---|---|
| Смысл значений `verification` | Докстринг `vast_probe.py`; комментарий у `VERIFICATION_FIELDS`; строка «Смысл значений не подтверждён (UNVERIFIED)» в выводе; поле `status` блока в JSON; строка журнала SPEC |
| Смысл значений `is_vm_deverified` | Те же места, что и для `verification` |
| Фильтр `verified` в запросе поиска | Комментарий у блока сверки (без изменений; живой ответ с этим ключом не получен, поиск с ним вернул 0) |

## 6. Риски

1. **Смысл значений `verification` неизвестен.** Проба печатает значения как есть и не сопоставляет их с «verified» или «unverified». Пока значения не расшифрованы, по ним нельзя отбирать карты и менять production-фильтр.
2. **Выборка мала.** Прогон дал 5 предложений без фильтра и 0 с фильтром. Значения могут не отражать весь рынок. Следующий прогон на GitHub даст новые значения, но тоже ограниченной выборкой.
3. **Поиск с `verified=True` дал 0 предложений.** Работает ли сам фильтр, не подтверждено: ключ `verified` в запросе не проверен живым ответом.
4. **Путь v0 не подтверждён.** Ответ 200 с `{"instances": null}` на несуществующий id не говорит, работает ли `GET /api/v0/instances/{id}/` для реальной карты. Риск раздела 8.3 открыт: нужен прогон с id существующей карты.
5. **Имя `verif` в фильтрованном выводе.** Поиск подстроки «verif» в `_verify_field_names` также находит `is_vm_deverified` (в слове «deverified» есть «verif»). Это поведение сохранено как было, но в выводе фильтрованного блока оба поля будут видны как «с подстрокой verif».
6. **Живой прогон после правки не выполнен.** Офлайн-проверка проверяет логику и маску секретов на заглушках, но не формат реального ответа Vast.
